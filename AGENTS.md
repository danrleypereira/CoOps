# AGENTS.md

Guidance for AI coding agents working in this repository. The goal is to
flag the things an agent is likely to miss, not to duplicate the docs
already in `README.md`, `ARCHITECTURE.md`, `RUNNING_LOCALLY.md`, and
`CONTRIBUTING.md` — read those first.

## Layout

Two independent projects in one repo:

- **Python ETL backend** (repo root, `pyproject.toml`): Medallion pipeline
  `src/coops/` — Bronze → Silver → Gold — installed as a real package via
  `uv sync`. Tests in `tests/`.
- **React dashboard** (`dashboard/`): Vite + React 19 + D3 + TypeScript,
  tested with Vitest.

Layout inside `src/coops/` (no flat `import utils.github_api` — import as
`from coops.utils.github_api import ...`):

```
coops/
├── etl/               # CLI orchestrators (bronze_extract, silver_process, …)
├── bronze/ silver/ gold/
├── utils/             # github_api, data_helpers
├── ai_analysis/       # optional Gemini module
├── domain/            # tenancy primitives
└── infrastructure/    # pydantic config
```

`data/` (bronze/silver/gold JSON), `data/master_registry.json`, and
`data/data_catalog.json` are **generated artifacts** committed back by
the GitHub Actions bots. Don't hand-edit; regenerate via the pipeline.

## Commands

Install once: `uv sync` (Python 3.10+, uv handles it). Then:

```bash
# ETL — pipeline order, same as CI on main
uv run coops-bronze --cache        # Bronze (writes data/bronze/)
uv run coops-silver                # Silver
uv run coops-gold                  # Gold timelines (+ optional AI if GEMINI_API_KEY set)
uv run coops-aggregate             # Executive KPIs / performance tiers
uv run coops-registry              # Refresh data/master_registry.json

# Tests — config lives in [tool.pytest.ini_options] in pyproject.toml
uv run pytest                              # unit + integration, --cov=coops baked in
uv run pytest tests/unit
uv run pytest tests/integration
uv run pytest tests/unit/test_xxx.py::test_yyy      # single test
# CI fails below: --cov-fail-under=60 (unit) / 70 (integration)

# Frontend (from dashboard/)
npm install
npm run dev                # http://localhost:5173
npm run test:coverage      # Vitest; thresholds 60% (vitest.config.ts)
npm run lint
npm run format
npm run build:gh           # production build used by deploy-pages.yaml
```

## Secrets / env

- `.secrets` at repo root (gitignored, template in `EXAMPLE.secrets`)
  holds `GITHUB_TOKEN`, `GITHUB_ORG`, optional `GEMINI_API_KEY`. Used
  by `act`/`gh act` and by `coops.ai_analysis`.
- The CLI entry points (`coops-bronze` …) read `GITHUB_TOKEN`/`GITHUB_ORG`
  from `.secrets` or the environment — no `--token` flag needed.
- **On GitHub**: secrets/variables **cannot** start with `GITHUB_`. Use
  `COOPS_GITHUB_TOKEN` (fine-grained PAT, `Members: Read-only`, public
  repos only) and `COOPS_ORG`. Default Actions token sees only public
  memberships — `unb-mds`-style concealed orgs need the fine-grained PAT.
  An expired `COOPS_GITHUB_TOKEN` fails Bronze at "Verify organization
  is valid" with HTTP 401.
- **`act` does NOT load `GITHUB_ORG` from `.secrets`** — pass
  `--var COOPS_ORG=<org>` explicitly or it falls back to the `origin`
  remote's owner.
- Frontend data source: `dashboard/src/services/dataSource.ts`. Default
  (`VITE_USE_LOCAL_DATA=false`) fetches
  `raw.githubusercontent.com/<org>/<repo>/main/data`. Set
  `VITE_USE_LOCAL_DATA=true` **and** symlink `data/` into
  `dashboard/public/data/` to develop against a local extraction:
  `mkdir -p dashboard/public && ln -s ../../data dashboard/public/data`.
  `dashboard/src/pages/VisualizationUtils.ts` builds `${BASE_URL}data/...`
  directly and **bypasses the flag**, so `public/data/` is needed
  regardless of `VITE_USE_LOCAL_DATA`.
- `available_repos.json` (fetched at root, outside `data/`) is **not**
  generated by any backend workflow today — its absence is silently
  logged, not fatal.

## CI / pipeline chain on `main`

`bronze-extract.yaml` → `silver-process.yaml` → `gold-process.yaml` →
`gold-aggregate.yaml` → `deploy-pages.yaml` (triggered via
`workflow_run`). Cron `0 5 * * *`, also push to / PR on `main`.

- `bronze-extract.yaml` exposes manual `workflow_dispatch` inputs for
  quick local tests: `max_repos`, `max_commits_per_repo`,
  `skip_structure`, `since` (ISO-8601), `max_issues`, `max_prs`. They
  are ignored on push/cron (full extraction runs). `max_issues`/`max_prs`
  share a paginated call — pagination only truncates when **both** are
  set; the blacklist/fork filter runs after `max_repos`, so a cap may
  return fewer repos than requested.
- `start.yaml` and `save-issues.yaml` are legacy/manual-only.
- `validate-pipeline.yaml` runs the Bronze → Silver → Gold chain against
  a real organization **without** committing data — use it for PR
  validation that needs real GitHub data.
- `python-unit-tests.yaml` runs on Python 3.10/3.11; `python-integration-tests.yaml`
  on 3.10/3.11/3.12.

## `act` / `gh act` quirks

Silver and Gold **need `--bind`** or they fail with
`fatal: not a git repository (or any parent up to mount point ...)` —
their "Pull latest data files" step runs without the `if: ${{ !env.ACT }}`
guard that Checkout has, and without `--bind` no git repo is mounted in
the container. Bronze's Checkout **does** have that guard, so `.secrets`
isn't wiped by `actions/checkout`'s default `git clean -ffdx`.

The container runs as root, so generated files end up `root:root` on
the host. Add `--container-options "--user $(id -u):$(id -g)"` to keep
ownership; if your `act` ignores it, `sudo chown -R $(whoami) .` (or
`sudo rm -rf .venv` if `uv sync --locked` rewrites it under root).

## Conventions

- **Conventional Commits** required (`feat:`, `fix:`, `docs:`, `refactor:`,
  `chore:`, `test:`, `ci:`, `perf:`, `style:`). Branch prefixes:
  `feat/`, `fix/`, `docs/`, `refactor/`, `chore/`, `hotfix/`. Squash
  merge; minimum 1 approval. PR template at
  `.github/PULL_REQUEST_TEMPLATE.md` (lists affected layers, asks for
  `CHANGELOG.md` update under `[Unreleased]` for user-visible changes).
- **License**: GPL-3.0-or-later; new source files need the GPL header
  (see `CONTRIBUTING.md`).
- **Docs**: `README.md` / `ARCHITECTURE.md` / `RUNNING_LOCALLY.md` are
  in English; `CONTRIBUTING.md` and `desenvolvimento.md` are in
  Portuguese.
- **Coverage excludes**: `coops/ai_analysis/*` and
  `*cleanup_event_data.py` (see `[tool.coverage]` in `pyproject.toml`).
- **JOSS paper** lives on the `paper` branch (`paper/paper.md`,
  `paper/paper.bib`, `paper/figures/`); don't touch it from a feature
  PR.
